먼저 알아 둘 것 저장소 루트의 README.md와 .env.example은 현재 구현과 어긋나 있습니다. 웹훅 경로가 /webhooks/gitlab으로 적혀 있으나 실제는 /webhooks/gitlab/mr이고, 승인자 설정도 SLACK_ALLOWED_USER_IDS가 아니라 REVIEWER_MAP으로 바뀌었습니다. 이 문서를 기준으로 삼으세요.
01

로컬에서 띄우기

요구사항

  • Python 3.12 이상
  • AI 기능을 켤 경우, 해당 CLI가 설치되어 있고 로그인된 상태여야 합니다 — 알림 요약은 claude, 리바이스·mrdoc의 단계 실행은 codex. 경로가 PATH에 없으면 CLAUDE_BIN / CODEX_BIN으로 지정합니다.
  • 리바이스를 켤 경우, 대상 저장소에 push 권한이 있는 GitLab 토큰

실행

python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -e ".[dev]"
uvicorn app.main:app --reload
  • 상태 확인 http://localhost:8000/health
  • API 문서 http://localhost:8000/docs
  • 테스트 pytest · 린트 ruff check .
워커는 반드시 1개 백그라운드 작업이 프로세스 안의 스레드와 큐로 돌아갑니다. 워커를 늘리면 같은 일을 여러 프로세스가 중복 수행하게 됩니다. uvicorn --workers 1을 유지하세요.
02

설정 전수

.env에 넣습니다. 아래는 app/config.py의 실제 필드와 기본값입니다. 환경변수 이름은 필드명을 대문자로 쓴 것입니다 (mrdoc_enabled → MRDOC_ENABLED).

필수 — 없으면 동작하지 않는다

키기본설명
GITLAB_URLgitlab.com 사내 GitLab 루트. /api/v4는 코드가 붙입니다
GITLAB_WEBHOOK_SECRET— 웹훅 검증용. 미설정이면 웹훅을 전부 거절합니다(fail-closed)
GITLAB_TOKEN— api scope. 승인·머지·push에 이 계정이 쓰입니다
SLACK_BOT_TOKEN— chat:write와 files:write 필요
SLACK_SIGNING_SECRET— Slack 요청 서명 검증
SLACK_CHANNEL_ID— 알림을 보낼 채널
ACTION_TOKEN_SECRET— 버튼에 심는 서명 키. 긴 임의값
REVIEWER_MAP빈 값 저장소별 승인자. 아래 §05 참조 — 비면 아무도 승인할 수 없습니다

레일 토글 — 무엇을 켤지

03

GitLab 웹훅 등록

대상 프로젝트의 Settings → Webhooks에 등록합니다.

https://<public-host>/webhooks/gitlab/mr
  • Secret token — GITLAB_WEBHOOK_SECRET과 같은 값
  • Trigger — Merge request events. 리바이스를 쓸 경우 Push events도 함께 (사람이 직접 push했을 때 봇이 물러나기 위해 필요합니다)
  • SSL verification — 활성화
  • 여러 프로젝트에 같은 URL과 같은 secret을 등록해도 됩니다. API 호출은 payload의 숫자 project id를 씁니다
04

Slack App 설정

  1. OAuth 권한에 chat:write와 files:write를 추가합니다.
    files:write가 없으면 리포트 첨부가 실패합니다 — 요약은 일반 메시지로 나가지만 리포트 파일은 오지 않습니다.
  2. 워크스페이스에 설치하고 알림 채널에 App을 초대합니다.
  3. Interactivity & Shortcuts를 켜고 Request URL을 등록합니다.
    https://<public-host>/webhooks/slack/actions
  4. 공개 URL을 만들기 어렵다면 Socket Mode를 대신 쓸 수 있습니다 — SLACK_SOCKET_MODE=true와 SLACK_APP_TOKEN이 필요합니다.
터널 주소가 바뀌면 GitLab 웹훅 URL과 Slack Request URL을 둘 다 갱신해야 합니다. 한쪽만 고치면 알림은 오는데 버튼이 죽거나, 그 반대가 됩니다.
05

승인자 — REVIEWER_MAP

승인 권한은 저장소별로 지정합니다. JSON 객체 하나이며, 키는 저장소 슬러그, 값은 Slack 사용자 ID 목록입니다.

REVIEWER_MAP={"group/project": "U111,U222", "group/other": ["U333"]}
fail-closed
  • 매핑에 없는 저장소는 승인자가 0명입니다. 아무도 버튼을 쓸 수 없습니다.
  • 그런 MR은 알림 단계에서 수동 처리로 전환되고 경고가 게시됩니다.
  • 새 저장소를 붙일 때 REVIEWER_MAP 추가를 잊으면 바로 이 증상이 납니다.
검사 시점은 두 번
  • 버튼을 누를 때 한 번
  • 의견 모달을 제출할 때 다시 한 번
  • 권한이 없으면 본인에게만 보이는 안내가 뜨고 아무 상태도 바뀌지 않습니다.
GitLab 쪽 제약 승인은 GITLAB_TOKEN 소유자 계정으로 기록됩니다. 프로젝트가 MR 작성자 승인이나 커미터 승인을 금지하고 있다면, 그 계정이 만든 MR은 승인할 수 없습니다.
06

단계별로 켜기

한 번에 다 켜지 마세요. 각 단계가 안정된 뒤 다음으로 넘어가는 순서입니다. 3단계부터 저장소에 쓰기가 발생합니다.

1단계
알림만
AI_ENABLED=false · AI_RUNNER=stub · mrdoc 꺼짐 — LLM 없이 알림과 승인 버튼만. 웹훅·서명·권한 매핑이 맞는지 여기서 확인합니다
↓
2단계
AI 요약
AI_ENABLED=true — 알림에 요약이 붙습니다. claude CLI 로그인 상태와 호출 시간을 확인합니다
↓
3단계
실제 수정
AI_RUNNER=staged — 의견이 커밋·푸시로 이어집니다. 테스트 저장소에서 먼저 돌려 보세요. push 권한과 봇 계정 설정을 확인합니다
↓
4단계
mrdoc 리포트
MRDOC_ENABLED=true + MRDOC_SATELLITE_ENABLED=true — 문서 MR에 변경 리포트가 붙습니다
↓
5단계
보완 경로
웹훅 유실이 관찰될 때만 POLL_ENABLED=true. 불필요하면 켜지 마세요 — API 호출만 늘어납니다
07

운영 — 막혔을 때

대부분의 문제는 세션이 manual(수동 처리)로 떨어지는 것으로 나타납니다. 이건 고장이 아니라 봇이 손을 떼고 사람에게 넘기는 정상 동작입니다. 중요한 건 왜 떨어졌는지입니다.

사유무슨 일이 있었나대응
guard_reject 이 저장소에 승인자 매핑이 없음 REVIEWER_MAP에 저장소를 추가하고 MR을 다시 여세요
human_push 봇이 수정하는 중에 사람이 직접 push 정상입니다. 사람이 그대로 이어서 진행하세요
revise_timeout 수정 작업이 제한 시간을 넘김 (재시작으로 유실된 경우 포함) 로그에서 어느 노드에서 멈췄는지 확인. 반복되면 타이머를 올리되 §02의 부등식 유지
revise_attempts_exceeded 재시도까지 모두 실패 작업 디렉터리의 산출물을 열어 어디서 막혔는지 확인하세요
merge_poll_failed 머지를 호출했으나 확인되지 않음 GitLab에서 MR 상태를 직접 확인. 충돌·승인 규칙 미충족이 흔한 원인입니다
push_during_merge 머지 진행 중 새 커밋이 들어옴 머지하지 않은 것이 맞습니다. 새 내용으로 다시 리뷰하세요
external_close MR이 봇 밖에서 닫힘 MR을 다시 열면 폴러가 켜져 있을 때 자동으로 복귀합니다

무슨 일이 있었는지 보는 법

  • 세션의 이력은 전부 event_log 테이블에 있습니다. session_id로 시간순 조회하면 전이와 이유가 그대로 남아 있습니다.
  • 리바이스 라운드의 중간 산출물은 WORKSPACE_ROOT 아래 라운드별 디렉터리에 번호 순으로 남습니다. 어느 노드까지 갔는지가 곧 파일 목록입니다.
  • mrdoc은 작업 디렉터리의 이력 파일에 웨이브별로 무엇이 성공·강등·실패했는지 적습니다.
재시작해도 안전한가 알림 발송은 안전합니다 — 미발송 건을 기동 시 다시 큐에 넣습니다. 진행 중인 수정 작업은 이어지지 않습니다 — 제한 시간이 지나면 수동으로 전환되며, 그때 사람이 이어받으면 됩니다.
08

알려진 결함

재발급된 승인 버튼이 동작하지 않는다 알림 후 작성자가 push하면 봇이 승인 버튼을 새로 발급하는데, 그 버튼의 서명 토큰이 검증을 통과하지 못합니다. 원인은 review_session에 제목·URL·브랜치 컬럼이 없어 토큰을 자리표시자로 채우기 때문입니다. 우회 — GitLab에서 직접 머지하거나, MR을 닫았다 다시 열어 새 알림을 받으세요.
비용 상한이 집행되지 않는다 예산 설정값은 읽히기만 하고 어떤 호출에도 전달되지 않습니다. 실질적인 통제는 타임아웃과 입력 문자 수 상한입니다.
재시작 시 진행 중 작업 유실 큐가 프로세스 메모리에 있어 재시작하면 대기·진행 중이던 라운드가 사라집니다. 스위퍼의 제한 시간이 지나야 수동으로 정리됩니다.
번호 매긴 질문 참조는 비어 있다 opinion.question_refs 컬럼은 항상 비어 있습니다. 해당 입력 기능이 제거되었고 컬럼만 남아 있습니다.
