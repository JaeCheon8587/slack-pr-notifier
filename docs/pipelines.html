MR 리뷰 봇 파이프라인

GitLab MR의 문서 변경을 Slack에서 리뷰하고, 의견대로 고치고, 승인까지 처리하는 서버입니다. 미들웨어 위에 파이프라인 두 개가 올라가 있습니다.

01

개요

하는 일

MR이 올라오면 문서 변경을 섹션 단위로 분석한 리포트를 Slack에 붙이고, 리뷰어 의견대로 문서를 고쳐 다시 올리고, 버튼으로 승인 · 머지합니다.

만든 이유

줄 단위 diff로는 문서가 무엇이 바뀌었는지 보이지 않고, 리뷰와 수정 요청 왕복을 사람이 매번 GitLab과 메신저를 오가며 합니다.

지금 구성

  • 사용GitLab 폴러 + Slack Socket Mode
  • 켜짐AI 요약 · MR 리뷰(mrdoc)
  • 배치별리바이스 — 기본값 AI_RUNNER=stub(꺼짐). .env는 배치마다 다르며, staged면 봇이 문서를 고쳐 MR 브랜치에 커밋·푸시합니다.
02

전체 흐름

모든 연결은 서버가 먼저 엽니다. GitLab은 주기적으로 조회하고, Slack에는 소켓으로 붙습니다.

  1. 1폴러가 새 MR을 발견하면 세션을 만들고 Slack 알림을 보냅니다. MR 리뷰 파이프라인이 리포트를 알림 스레드에 붙입니다.
  2. 2[변경 요청]을 누르면 리바이스가 문서를 고쳐 커밋 · push하고, 새 라운드 알림과 리포트가 옵니다. MR당 최대 3라운드.
  3. 3[승인]을 누르면 리뷰어가 본 커밋으로 고정해 머지합니다. 머지는 사람 승인으로만 일어납니다.
03

미들웨어

이벤트를 받고, MR마다 상태를 기록하고, 파이프라인을 실행하는 서버입니다. 모든 상태 변경은 상태 기계 한 곳을 거칩니다.

세션 상태reviewing리뷰 대기 · revising수정 중 · merging머지 확인 중 · manual사람 처리 · merged완료

gitlab_poller

60초마다 GitLab API로 열린 MR을 조회해 DB와 비교합니다. 새 MR, 커밋 변경, 닫힘 · 머지, 다시 열림을 찾아 ingest로 넘깁니다.

slack_socket

Slack에 WebSocket으로 붙어 버튼 · 모달 입력을 받고, 바로 응답한 뒤 slack_dispatch로 넘깁니다.

ingest

MR 이벤트를 처리합니다. 세션 생성, 알림 발송, MR 리뷰 기동, 사람 push와 외부 머지 · 닫힘 처리.

slack_dispatch

[승인]은 머지 절차로, [변경 요청]은 의견을 저장한 뒤 리바이스 큐로 보냅니다.

state_machine · db

허용된 전이만 CAS로 바꾸고, 모든 전이를 event_log에 남깁니다.

revise_executor

리바이스 작업 큐와 워커 1개. 결과를 커밋 · push하고 라운드 알림을 보냅니다.

mrdoc.rail

MR 리뷰를 백그라운드 스레드로 돌리고 결과를 알림 스레드에 올립니다.

sweeper

머지나 수정이 제시간에 끝나지 않은 세션을 manual로 넘깁니다.

코드에는 GitLab 웹훅(gitlab_webhook)과 Slack HTTP(slack_actions) 입구도 있습니다. 같은 처리기로 이어지지만 지금 구성에서는 쓰지 않습니다.

05

MR 리뷰 파이프라인

문서 변경을 섹션 단위로 쪼개 분류하고 리포트로 만듭니다. 변경 파일의 80% 이상이 .md / .mdx인 MR에서 돌고, 산출물 파일이 있으면 그 노드는 끝난 것으로 봅니다.

changeset도구00-changeset

MR의 변경 파일과 변경 줄 범위를 정리합니다.

structure도구05-structure

전후 문서를 섹션 트리로 만들어 짝짓고, 바뀐 섹션 하나를 변경 유닛 하나로 만듭니다.

literals도구06-literals

유닛마다 숫자 · 버전 · 단위 · 키-값의 전후 차이를 뽑습니다.

excerpt도구07-excerpt

LLM에 줄 원문 발췌를 만듭니다. 문서 본문이 들어가는 유일한 산출물입니다.

analysisLLM20-analysis/

파일 묶음마다 유닛 설명, 분류 주장, 파일 요약을 씁니다.

levelcheck도구30-levelcheck

분류를 도구 증거로 확정합니다. 값이 바뀌었으면 의미(값)로 올리고 평가 표현 금지어를 잡습니다.

verifierLLM40-verifier

설명이 원문과 맞는지 유닛마다 판정하고 개수를 대조합니다. 고칠 대상은 FIX로 남깁니다.

themesLLM45-themes

유닛 목록만 받아 주요 변경을 주제로 묶습니다.

collect도구50-collect

모든 결과를 합치고 집계합니다. 리포트와 Slack 요약이 이 하나에서 나옵니다.

render도구report.html

report.html과 Slack 요약 텍스트를 만듭니다.

재작성이 실패하면 이전 결과로 복원한 뒤 리포트까지 진행합니다. 검증하지 못한 설명은 리포트에 "미검증"으로 표시합니다.

06

리바이스 파이프라인현재 꺼짐 · 실사용 검증 전

리뷰어 의견대로 문서를 고쳐 MR 브랜치에 커밋합니다. LLM이 낸 결과는 다음 도구 노드가 검사하고, 걸리면 원인에 맞는 단계로 돌려보냅니다.

intent · 3aLLM · 읽기 전용00-intent

의견을 대상 문서, 작업 종류, "A → B" 수정 방향, 검색어로 구조화합니다.

anchor도구10-anchor

검색어로 고칠 섹션을 찾습니다. 못 찾으면 가까운 후보 3개로 되묻습니다.

spec도구15-spec

3a 스펙을 의견 원문 · 섹션과 대조하고, 바꿀 현재 값 A를 섹션에서 확정합니다. 이미 반영된 의견은 여기서 닫습니다.

impact도구20-impact

같은 값이나 링크를 가진 다른 섹션을 함께 고칠 후보로 둡니다.

edit · 3bLLM · 쓰기30-edit

허용된 파일 안에서만 문서를 편집합니다. 쓰기 권한은 이 노드에만 있습니다.

gate도구35-gate

허용 밖 파일과 문서가 아닌 파일은 되돌리고, A → B 치환 여부와 변경 크기를 검사합니다.

verify · 3cLLM · 읽기 전용40-verify

diff를 보고 의견마다 반영 · 부분 반영 · 미반영을 판정합니다.

summary도구50-summary

반영 판정을 받은 편집만 커밋 대상으로 남기고, 변경 요약과 미반영 목록을 만듭니다.

07

회고

잘 된 것

  • LLM 결과를 다음 도구 노드가 검사하는 구조. 분류 확정, 스펙 대조, 편집 게이트.
  • 산출물 파일로 진행 상태를 판단해서 중간부터 다시 시작할 수 있음.
  • 밖에서 들어오는 연결 없이 동작. 폴러 + Socket Mode.
  • 검증하지 못한 것은 "미검증"으로 표시하고 정상으로 숨기지 않음.

부딪힌 문제

  • LLM의 조용한 실패. 성공이라고 하고 산출물이 없음. 파일 존재와 파싱으로 판정하게 바꿈.
  • 프롬프트 템플릿과 파서 불일치. 템플릿을 파서 쪽 렌더러로 생성하게 바꿈.
  • 분류 과대 주장과 평가 어휘. 도구 증거로 승격하고 금지어로 막음.
  • 문서와 코드의 어긋남. 이번 감사에서 약 120건.

남은 과제

  • 리터럴 검증에 떨어진 편집이 재시도를 다 쓴 뒤 커밋될 수 있음.
  • 리바이스가 제한 시간을 넘기면 이전 실행과 재시도가 겹칠 수 있음.
  • 리바이스 주의 항목이 Slack까지 전달되지 않음.
  • 리바이스 실사용 검증은 MR !47에서 1회 했고, 아래 세 건이 그때 드러났습니다.
  • edit 산출물 파서가 여러 줄 리스트와 프론트매터 앞 산문을 거부해, 내용이 멀쩡한 산출물이 형식 때문에 폐기됨(라운드 2회 연속 abort).
  • 의견 하나에 지시를 여럿 담으면 스펙이 from/to를 null로 떨어뜨리고 기계 대조를 건너뜀 — 결정론 게이트가 스스로 꺼짐.
  • edit이 원문을 읽지 않고 “이미 목표 상태”라 단정한 사례. 게이트가 꺼진 상태에선 걸러낼 장치가 없음.
  • 재시작하면 진행 중이던 리바이스가 사라짐.
  • MR을 쓰지 않는 팀에 적용하는 방법.
