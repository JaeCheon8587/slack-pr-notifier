왜 Read 까지 빼나

Read 가 있으면 20-analysis/*.md 를 읽고 판단을 형성할 물리적 경로가 생긴다. 200턴을 도는 동안 프롬프트는 잊히고 도구는 남는다.

HARD LIMITS

  1. 산출물 본문을 읽지 않는다. 읽으면 finding 을 만들기 시작한다. 상태가 필요하면 mrdoc status. 도구 미부여로 물리적 차단
  2. 위성이 준 숫자를 합산하지 않는다. 합산하면 리포트 숫자의 출처가 두 곳이 된다. 합산은 mrdoc collect. ledger 에는 리턴을 원문 그대로
  3. 위임 스펙을 직접 작성하지 않는다. dispatch 출력을 그대로 붙인다. 부실해 보이면 그건 dispatch 버그다
  4. 팬아웃 5 초과 금지. 한 wave 를 여러 메시지로 쪼개지 않는다. 쪼개면 조인 지점이 사라진다
  5. 위성을 임의로 재호출하지 않는다. 재호출은 비결정성의 유일한 입구다. 리턴 유실은 mrdoc status --receipt 로 회수
  6. exit code 를 무시하지 않는다. 0/4/2 이외는 abort

「관련 문서를 다 읽고 지목」이 아니다. 표지만 훑어서 읽을 곳을 찍는다. 지목된 절을 실제로 읽는 건 doc-analyzer — 역할과 예산(8 / 16)이 갈려 있다. failover.md 도입부가 "장애 복구 절차와 재시도 정책"이고 목차에 7.2 재시도 가 있으면 그걸로 지목이 끝난다.

base 본문을 반드시 읽는 이유

head 만 보면 없어진 주제를 참조하는 절을 못 찾는다. 링크는 살아있고 내용만 없어진 경우 — 문서 리팩터링 MR 의 주된 실패 유형이다.

HARD LIMITS

  1. 판정하지 않는다. "모순이다" 는 analyzer 의 일. 지목하고 why 에 근거만 쓴다
  2. 절 본문을 통독하지 않는다. 18파일 통독하면 죽는다. 도입부 intro_lines 줄 + heading 트리만. 변경 절만 예외
  3. 검색어를 만들지 않는다. probe·keyword 류 필드가 스키마에 없다. 위치(section_id)로 지목한다
  4. 지도를 만들지 않는다. 재사용 가능한 주제 인덱스를 산출하지 않는다. 이번 MR 의 TARGET 만. 자산화는 측정 후 별도 결정
  5. FILES_SCANNED 를 실제 값으로 쓴다. 모자라면 PARTIAL + UNCOVERED. 18/18 거짓 기재는 커버리지 오보

왜 리턴만으로는 안 되는가

위성 공통 규약 Report-first(첫 2 툴 호출 안에 스켈레톤 생성)와 RECEIPT copy(529 유실 시 회수)는 산출물 파일이 있어야 성립한다. 리턴만 두면 verifier 혼자 두 규약의 예외가 되고, 죽으면 판정이 같이 사라져 재호출밖에 답이 없다 — 재호출은 비결정성의 유일한 입구다.

  • collect 가 직접 읽는다. 35-collect frontmatter 의 verify: {rounds, verdict, outstanding} 출처가 파일로 확정된다 — 오케스트레이터가 데이터 경로에서 빠진다
  • dispatch 가 재호출 스펙을 만든다. REQUIRED FIXES 상세를 파일에서 읽어 CONTEXT·CONSTRAINTS 를 결정론적으로 생성한다. 리턴에는 개수만 싣는다
  • 오케스트레이터가 받는 것은 두 개뿐이다. REPORT 경로 + VERDICT. 본문은 읽지 않는다 — 읽으면 finding 을 만들기 시작한다

HARD LIMITS

  1. 남의 산출물을 수정하지 않는다. 고치면 저자가 되고 fresh context 가 무의미해진다. Write 가 부여됐으므로 이제 물리적 차단이 아니라 규약이다. Write 는 32-verify.md 한 개에만. 20-analysis/*.md 는 안 건드리고 REQUIRED FIXES 에 번호 + 대상 id 만
  2. 애매하면 APPROVE 하지 않는다. 부당한 APPROVE 가 이 계층을 없앤다. REVISE + 이유
  3. 원문 안 읽고 판정하지 않는다. 읽은 것만 CHECKED. 못 읽은 항목은 판정하지 않고 UNCOVERED
  4. 문서 내용의 옳고 그름을 판정하지 않는다. 분석의 충실도만. 이상해 보이면 UNCERTAIN 한 줄
  5. verdict(BLOCK/REVIEW/PASS)를 언급하지 않는다. 그건 collect 의 rule. 서술 충실도와 레벨만

CHECKED 의 의미는 reviewer.md 그대로 — "what you actually read, not what you were pointed at." 원문을 안 읽은 APPROVE 는 고무도장이다.

이 한 줄이 "조용한 누락 금지"의 유일한 집행 수단이다. optional 필드는 LLM 이 안 쓰고, 그러면 "해당 없음" 과 "안 함" 이 구분되지 않는다. 자기보고와 툴 실측이 이중화된다 — 자기보고 none 인데 실측 미응답 >0 이면 거짓 영수증이고, 재호출 없이 analysis_failed 다. CONFIDENCE 는 severity 계산에 쓰지 않는다 — must_read 정렬과 표시에만.
