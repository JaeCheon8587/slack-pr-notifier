LLM 자리는 3개 — 구조화(3a) / 선별+편집(3b) / 대조 검증(3c). 세 자리는 각각 별도 codex exec 호출이고, 사이의 존재검사 · 스펙 대조 · 역검색 · 게이트 · 추출은 Python 결정론 노드다. 집행 수단은 샌드박스와 게이트다 — 프롬프트로 금지하는 것과 기계가 막거나 되돌리는 것은 다르다.

에스컬레이션은 스펙 재투입을 세지 않는다 v1.2 — 스펙 재투입은 3b 가 아니라 3a 를 다시 돌린 것이라 「앞선 편집 시도」가 아니다. 이걸 세면 스펙 반려 한 번 뒤의 첫 3c 미반영이 3b 를 건너뛰고 곧장 3a 로 간다. 같은 이유로 3b 재투입 메모(_retry_note)에는 스펙 반려 줄을 싣지 않는다 — 3b 가 답할 지적이 아니다.
재투입 대상은 3b 에 실제로 보낸 의견뿐이다 실측 · v1.2 확장 — MISSING 과 clarify 는 되물음, 이미 반영은 종결이지 구현 누락이 아니다. 3c 미반영 재투입은 유효 뷰(스펙 ok · FOUND)의 의견으로만 한정한다.

사람이 정한 네 가지

A 를 누가
코드가 결정한다. 3a 의 A 는 목차만 본 추측이라 채점 기준으로 쓸 수 없다. 코드가 고친 A 는 주의 항목에 「스펙의 현재 값 '3.1' 을 절의 같은 종류 값 '3.2' 로 교정했다」로 남는다
약한 앵커
진행 + 주의 표기. 막으면 고칠 수 있던 의견까지 사람에게 되돌아가고, 조용히 진행하면 엉뚱한 절을 고친 사실이 묻힌다 — 「약한 앵커」 · 「모호한 앵커」 줄이 리포트에 실린다
다중 출현
절 안 전부 치환. 개수는 스펙 게이트가 세서 3b 에 준다. 절 밖의 같은 값은 impact 의 동반 후보다

반영 완료 처리. 편집할 것이 없는 의견을 미반영으로 두면 다음 라운드에 계속 돌아온다

구현하며 정한 것

  • 이미 반영은 강한 앵커일 때만 — 약한 앵커에서 「B 가 있다」는 엉뚱한 절을 본 결과일 수 있다. 확신 없는 applied 는 거짓 영수증이다
  • 원문이 명시한 값은 유사값으로 대체하지 않는다 — 사람이 3.2 라고 썼는데 절에 13.2 만 있으면 A 는 미정이다. 사람의 말이 추론보다 위다
  • 원문에 있다고 다 A 는 아니다 — 「3.2 에서 3.3 으로 올려 주세요. 4.0 은 유지.」의 4.0 은 지킬 값이다. 유지 표현이 붙은 값은 빼고, B 앞에 쓴 치환의 출발 값이 있으면 그 밖의 언급은 맥락으로 본다. 조사가 붙은 단위(30초를 · 10초는)도 원문에서는 떼어 읽는다 (app/mrdoc/literals.py 는 건드리지 않음)
  • B 가 이미 절에 있으면 추론하지 않는다 — 「타임아웃 60초, 재시도 간격 10초」에서 60초로 바꾸라는 의견의 남은 같은 종류 값(10초)은 건드리면 안 될 값일 수 있다. 확신 없는 편집 대신 그 값을 후보로 되묻는다
  • create + 치환은 모순 — 새로 만드는 내용에는 바꿀 현재 값이 없다
  • 막힌 의견은 3c 에 보내지 않는다 — 판정은 코드가 낸다(3c 카드)

35-gate.md가 LLM 보고를 믿지 않고 기계로 확인한다. 게이트는 판정하고, 되돌린다 — 그 판정을 근거로 무엇을 커밋할지는 오케스트레이터가 정한다.

#검사방법위반 시
1경로 화이트리스트git diff --name-only 가 전부 .md/.mdx 이고 전부 앵커/동반 후보 파일 집합 안인가부분 벗어난 그 파일만 되돌린다
2리터럴 실증의견이 「A → B」 치환을 요구했다면(A 는 스펙 게이트가 확정한 값) extract_literals 차집합 + 절 평문 검사부분 해당 의견을 failed_opinion_ids 로 → 3b 재투입
3규모 상한변경 파일 수 / 라인 수 상한 초과전량 전량 되돌리고 kind=failed
4잔여물 검사워크스페이스에 untracked 파일이 생겼는가부분 삭제. checkout -B 는 untracked 를 지우지 않는다
리터럴 실증세 항의 차집합을 직접 조립한다
A ∈ literals(base 유닛)   # 옛 값이 있었고
A ∉ literals(head 유닛)   # 사라졌고
B ∈ literals(head 유닛)   # 새 값이 생겼다

# 평문 병행 — 리터럴이 아니어도 항상 본다 (v1.2: 첫 줄 추가)
A in text(base 유닛)       # a_in_base_text — 없으면 fail
A not in text(head 유닛)   # a_in_head_text = false
B in text(head 유닛)       # b_in_head_text = true
⚠️ 함정 1 — 출현 횟수가 사라진다. extract_literals 는 (kind, key, value) 로 완전 dedup 한다. 「3곳 중 3곳 다 치환됐나」는 게이트에서 판정 불가 — 「그 값이 head 유닛에 더는 없다」까지만 말할 수 있다. 템플릿의 occurrences 가 unavailable 인 이유다. v1.2 대신 스펙 게이트가 편집 전 base 절에서 A 를 직접 세어(_count) 3b 에게 「N곳 — 전부 바꾼다」를 준다. 「하나라도 남았나」는 게이트의 a_in_head_text 가 잡는다.
⚠️ 함정 2 — 평문 용어 교체는 안 걸린다. 리터럴 6종(kv/unit/version/bool/code/link) 밖의 평문 교체는 아예 잡히지 않는다 → markdown_tree.section_text + 문자열 in 검사를 병행해야 한다. 템플릿의 text 슬롯이 그것이다.
⚠️ 함정 3 — 공허한 통과 v1.2 에서 막음 — A 가 base 절에 원래 없었다면 「A 가 head 에 없다」는 아무것도 증명하지 않는다. 평문 검사는 리터럴이 아닌 A 에서 sets 없이 혼자 판정하므로 여기서 새어 나갔다. 이제 a_in_base_text 가 거짓이면 fail 이고 STATUS 에 「치환 전 값이 base 절에 없음 N건」이 붙는다. 스펙 게이트가 A 를 절에서 확정하므로 정상 경로에서는 걸리지 않는다 — 스펙 게이트를 우회한 산출물에 대한 백스톱이다. 필드가 없는 v1 산출물은 true 로 읽는다.
⚠️ UnitLiterals.changed 를 믿지 말 것. 같은 키의 값이 여러 개일 때 정렬 후 위치로 zip 해 from→to 를 만들기 때문에 매핑이 어긋날 수 있다. 단일 치환 검증에는 위 3항 차집합을 직접 조립한다.

미결 사항

  1. 「라운드 1 차감」의 정확한 의미. round 미증가로 해석했다. round - 1을 의도했다면 0에서 음수가 되는 경우의 가드가 별도로 필요하다
  2. 같은 파일에 성공 의견과 실패 의견의 편집이 섞였을 때. 파일 단위로만 분리 가능하다. 현재 구현은 「성공 의견이 만진 파일만 커밋」이고 그 귀속은 편집 영수증으로 한다. 더 엄격하게 가려면 편집을 의견 단위로 직렬화해야 하는데 호출 수가 늘어난다
  3. 대상 문서가 많을 때의 3b fan-out. 호출 3회 결정을 유지하면 배치 분할이 필요하다. mrdoc 의 fanout(기본 5) 패턴을 그대로 쓸 수 있으나 이는 단계 수가 아닌 같은 단계의 병렬 배치다
  4. 「커밋 없는 라운드」의 처리 규칙이 문서에 없다. 테스트(test_no_commit_round_sends_none_diff_stat_and_compare_url)로만 굳어져 있다. 이번 개정에서 같이 명문화하는 것이 좋다
  5. ai_max_budget_usd를 단계별로 쪼갤지 호출당 그대로 둘지 — 정리됨. 단계별 revise_stage_budget_usd 를 둔다. 값도 실측으로 정했다: 3b $0.247(5턴), 3c 무도구 $0.0287(1턴). 같은 입력에서 턴 수가 약 2배까지 흔들려 $0.5 는 실측 $0.247 짜리 단계를 떨어뜨렸다 — 상한은 폭주를 막는 장치이므로 실측의 ~6배인 1.5로 둔다. v1.1 codex 에는 이 플래그가 없어 지금은 설정 호환용이다
  6. revise 라운드 뒤 mrdoc 이 다시 돌지 않는다. 재알림은 render_review_report 3슬롯 리포트로 나가고, mrdoc 매트릭스 리포트는 첫 리뷰의 것 그대로다. 수정 커밋 기준으로 mrdoc 을 다시 돌릴지는 정하지 않았다
  7. codex 샌드박스에는 도구별 차단이 없다. read-only 인 3a · 3c 도 워크스페이스 본문을 읽을 수 있고, workspace-write 인 3b 는 셸을 쓸 수 있다. 「3a 는 목차만」 · 「3c 는 diff 만」은 지금 프롬프트 HARD LIMIT 에만 기대며, 어겼는지를 기계가 보지 않는다. 3b 의 경로 이탈은 게이트가 여전히 되돌린다
  8. 스펙 게이트의 A 확정은 리터럴 치환에서만 강하다. 평문 용어 교체(리터럴 6종 밖)는 3a 의 A 를 절에서 문자열로 찾기만 하고, 같은 종류 유일 값 추론(3순위)은 리터럴에만 작동한다. 평문 A 도 B 도 절에 없으면 spec_error 로 3a 에 돌아간다
